QUICK FACT
--------------------------------------------------------------------------------
Our headline result : PR-AUC 0.795  (Random Forest + SMOTE-ENN, time split)
Typical papers      : PR-AUC 0.83-0.88  (same dataset, random split)
Highest published   : PR-AUC 0.988  (KAIS 2026, PRIVATE bank data)

This file explains why the difference exists, why we deliberately chose the
harder protocol, and why that makes our numbers MORE credible - not worse.

--------------------------------------------------------------------------------
1. WE NEVER LET THE TEST SET TEACH ANYTHING
--------------------------------------------------------------------------------
Common paper practice          | What we do instead
-------------------------------|------------------------------------------------
Tune hyperparameters on test   | Optuna objective = VALIDATION PR-AUC only
Pick threshold on test         | Threshold = max-F1 on VALIDATION, frozen
                               | before test; recorded per run in the CSV
Select best epoch by test      | Early stopping on validation PR-AUC only
Choose model by test results   | Model selection on validation; test scored ONCE

Every adaptive decision in our pipeline touches only the 42,721-row
validation window. The 42,722-row test set is opened exactly once per
configuration, after everything is frozen. You can verify this: frozen
thresholds span 0.07 to 1.0 across runs (results_classical.csv), proving
they were learned, never defaulted.

--------------------------------------------------------------------------------
2. WE SPLIT BY TIME, NOT BY SHUFFLE - MEASURED COST: ~ +0.02 TO +0.06 INFLATION
   REMOVED
--------------------------------------------------------------------------------
Fraud patterns drift day to day. Deployment reality = train on PAST,
score FUTURE. A shuffled split lets Tuesday's frauds teach the model about
Monday's test frauds - information that cannot exist in production.

We did not argue this - we MEASURED it (Family I, results_random_split.csv):

    Config                 TIME   RANDOM  Inflation from shuffling
    CatBoost + GAN         0.780   0.840      +0.060
    MLP raw                0.779   0.827      +0.047
    XGBoost + SMOTE-ENN    0.777   0.810      +0.034
    RandomF + SMOTE-ENN    0.795   0.812      +0.017
    LSTM + weight          0.780   0.797      +0.016
    GraphSAGE + weight     0.739   0.695      -0.044 (reversed!)

When WE run the papers' protocol, our scores move into the same band the
papers report. That closes the debate: the benchmark gap is dominated by
protocol, not model quality. Independent confirmation: EAI ISMLA 2026 states
chronological validation yields lower scores than random stratified evaluation.

Erratum: an initial run cached one GAN generator across both split arms,
inflating the random-arm CatBoost+GAN cell to 0.877 / +0.097. The cache is now
keyed by a hash of its training data; values above are from the corrected,
fully re-measured ablation.

--------------------------------------------------------------------------------
3. RESAMPLING NEVER TOUCHES VALIDATION OR TEST
--------------------------------------------------------------------------------
Many papers apply SMOTE BEFORE splitting, so synthetic copies of a fraud
land in both train and test - near-duplicate leakage that inflates recall
and F1. We apply every sampler (SMOTE / SMOTE-ENN / RUS / GAN) to TRAINING
rows only; val/test keep the true 578:1 distribution. Our CatBoost+GAN
ablation shows exactly how big this leak can be (up to +0.06 under shuffling).

--------------------------------------------------------------------------------
4. WEIGHTS AND THRESHOLDS ARE LEARNED FROM DATA, NOT ASSUMED
--------------------------------------------------------------------------------
Classic recipe: scale_pos_weight = n_negative / n_positive (~519 here).
We proved blindly using it collapses LightGBM (PR-AUC 0.009, 4,894 false
positives). Fix applied everywhere:
  - boosted trees: weight selected on VALIDATION grid {1,4,16,sqrt(r),64,r}
  - Optuna searched the weight freely and independently chose moderate
    values (4.1 / 14.9 / 73.5 / 172) - two independent mechanisms agreeing.
Papers that hard-code extreme weights without validation risk shipping the
LightGBM-style failure without noticing.

--------------------------------------------------------------------------------
5. HONEST UNCERTAINTY REPORTING
--------------------------------------------------------------------------------
The test window contains 52 real frauds. Any single-run metric therefore
carries roughly +/-0.02 noise. We treat differences below that as ties
(e.g., tuned RF 0.7936 vs untuned champion 0.7947 = statistical tie),
instead of claiming a winner from noise - a practice rare in this
literature, where 0.001 leaderboard gaps get celebrated.
